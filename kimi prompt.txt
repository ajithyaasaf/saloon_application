## 1. Existing `apps/customer-mobile` State & Monorepo Audit

### 1.1 Directory & Workspace State

- **Workspace Location**: `apps/customer-mobile`
- **Current Files**: `.gitkeep` only.
- **Root Workspace Integration**: `pnpm-workspace.yaml` declares `'apps/*'` and `'packages/*'`, making `apps/customer-mobile` a first-class package within the Turborepo monorepo.
- **Dependencies Available for Reuse**:
  - `@saloon/shared-types` (v0.0.1): Canonical domain DTOs, enums (`BookingStatus`, `PaymentMethod`, `Gender`, `FileCategory`), API envelopes (`ApiResponse<T>`, `PaginatedResult<T>`).
  - `@saloon/shared-utils` (v0.0.1): `ApiClient`, `ITokenStorage`, `formatINR`, `calculateGST`, `normalizeIndianPhone`, `isValidIndianPhone`, `timeStringToMinutes`, `minutesToTimeString`, `maskPhone`, `maskEmail`, `formatBytes`.
  - `@saloon/config` (v0.0.1): `API_ROUTES` dictionary (80+ endpoints), `PLATFORM_CONSTANTS` (IST timezone, currency defaults, upload size limits).
  - Backend API (`apps/api`): 13 production-ready modules covering OTP auth, customer self-service, booking, payment, reviews, loyalty, wallet, and the Phase 20 File & Media Engine.

### 1.2 What Must Be Created

1. **Application Foundation**: Expo SDK 51+ / React Native project configuration (`package.json`, `app.json`, `tsconfig.json`, `metro.config.js`, `eas.json`, `jest.config.js`).
2. **Token Storage Layer**: `SecureStoreTokenStorage` implementing `ITokenStorage` using `expo-secure-store` (iOS Keychain / Android Keystore).
3. **Navigation Infrastructure**: `@react-navigation/native` with `@react-navigation/bottom-tabs` and `@react-navigation/native-stack`.
4. **Mobile Design System**: Reusable luxury dark glassmorphic components (`Button`, `Card`, `Input`, `Badge`, `BottomSheet`, `Header`, `Skeleton`, `EmptyState`, `Toast`).
5. **Customer Domain Services**: Typed client wrappers consuming `API_ROUTES` via `ApiClient`.
6. **Feature Screens**: Complete customer journey (Auth, Discovery, Salon Details, Service Selection, Booking & Checkout, My Bookings, Wallet & Loyalty, Customer Profile, Reviews, Notifications).

## 5. Design System & Visual Tokens

### 5.1 Color System & Aesthetic

- **Theme**: Luxury Dark Glassmorphic Palette (consistent with Web Dashboard & Brand Identity).
- **Background**: `#090D16` (Deep Obsidian / Midnight).
- **Card / Surface**: `#111827` (`rgba(17, 24, 39, 0.85)` with subtle `1px solid rgba(255, 255, 255, 0.08)` border).
- **Primary Accent**: `#6366F1` (Electric Indigo / Blurple).
- **Secondary Accent**: `#A855F7` (Royal Purple).
- **Success**: `#10B981` (Emerald Green).
- **Warning / Star Gold**: `#F59E0B` (Amber Gold).
- **Danger / Error**: `#EF4444` (Ruby Red).
- **Text Primary**: `#FFFFFF` (Pure White).
- **Text Secondary**: `#94A3B8` (Slate Muted).
- **Text Accent**: `#818CF8` (Light Indigo).

### 5.2 Typography & Spacing

- **Font Families**: System Sans / Roboto (Android), San Francisco (iOS).
- **Scale**: Display (`28px`, bold), Heading 1 (`22px`, bold), Heading 2 (`18px`, semibold), Body (`15px`, regular), Caption (`12px`, medium), Micro (`10px`, semibold).
- **Spacing Grid**: 4px baseline (`4`, `8`, `12`, `16`, `20`, `24`, `32`, `40`).
- **Border Radius**: Small (`8px`), Medium (`14px`), Large (`20px`), Full / Pill (`9999px`).

### 5.3 Reusable Native UI Primitives (`src/components/ui/`)

- `AppButton`: Variants (`primary`, `secondary`, `outline`, `ghost`, `danger`) with integrated loading spinner.
- `AppCard`: Glassmorphic card surface with standard elevation, padding, and border glow.
- `AppInput`: Clean text input with label, left/right icon slots, error feedback, and phone prefix support (`+91`).
- `AppBadge`: Status pills mapping `BookingStatus` and `PaymentStatus` to semantic colors.
- `AppHeader`: Reusable navigation bar with back button, screen title, and optional action buttons.
- `BottomSheet`: Gesture-driven modal drawer for slot picking and filter selection.
- `SkeletonLoader`: Pulsing skeleton placeholder for async data loading.
- `EmptyState`: Contextual icon, title, description, and call-to-action button.
- `Toast`: Transient feedback banner for network errors, booking confirmations, and copied referral codes.

## 6. Authentication & Secure Session Lifecycle

```
[Customer on PhoneLoginScreen]
```

       │

       │ 1. Submits Phone Number (+91 9876543210)

       ▼

[authService.sendOtp()] ───────► POST /api/v1/auth/otp/send

       │

       │ 2. Enters 6-Digit OTP on OtpVerificationScreen

       ▼

[authService.verifyOtp()] ─────► POST /api/v1/auth/otp/verify

       │

       │ 3. Receives { tokens: { accessToken, refreshToken }, user }

       ▼

[SecureStoreTokenStorage] ────► Stores in Hardware Keychain / Keystore (expo-secure-store)

       │

       │ 4. Updates React AuthContext (user, isAuthenticated = true)

       ▼

[RootNavigator] ──────────────► Transitions from AuthStack to MainTabNavigator

       │

       │ 5. If Access Token Expires (401 Intercepted)

       ▼

[ApiClient Mutex Queue] ───────► POST /api/v1/auth/refresh (Single Flight)

       │

       ├──► Success: Stores Fresh Token & Automatically Retries Failed Requests

       └──► Failure: Clears SecureStore & Redirects to PhoneLoginScreen

## 7. Media Integration (Phase 20/21/22 Direct Cloud Pipeline)

Customer avatar updates and review photo uploads strictly use the **Presigned Direct-to-Cloud Upload Pipeline**:

```
[Customer Mobile: ImagePicker]
```

       │

       │ 1. Picks photo from Camera / Library (expo-image-picker)

       ▼

[mediaService.initiatePresignedUpload()]

       │

       │ 2. POST /api/v1/media/upload/presigned ({ category, mimeType, fileSizeBytes })

       ▼

[@saloon/api: MediaController] ──► Generates PENDING FileAsset + Signed R2/S3 Upload URL

       │

       │ 3. PUT binary stream directly to Cloudflare R2 / AWS S3 (with progress)

       ▼

[Cloud Storage: R2 / S3]

       │

       │ 4. POST /api/v1/media/upload/\:id/finalize

       ▼

[@saloon/api: MediaController] ──► Transitions FileAsset to READY & returns publicUrl

## 10. Testing Strategy

1. **Unit & UI Primitive Tests (****`src/tests/ui-primitives.spec.tsx`****)**:
   - Verify `AppButton`, `AppCard`, `AppInput`, `AppBadge`, and `SkeletonLoader` render correctly across all states (loading, disabled, error).
2. **Authentication Flow Tests (****`src/tests/auth-flow.spec.tsx`****)**:
   - Mock `SecureStore` and verify OTP send, OTP verify, session restoration on app launch, and logout storage purge.
3. **Booking Flow & Calculation Tests (****`src/tests/booking-flow.spec.tsx`****)**:
   - Test service price summing, GST calculation (`calculateGST`), coupon discount application, and slot selection state transitions.
4. **Domain Services Integration Tests (****`src/tests/domain-services.spec.ts`****)**:
   - Mock `ApiClient` and verify request parameters, query string serialization, and response envelope unwrapping.

## 13. Risks & Mitigations

| **RiskImpactMitigation Strategy**       |                                                 |                                                                                                        |
| --------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Monorepo Symlink Resolution (Metro)** | Metro failing to resolve `@saloon/shared-types` | Configure `metro.config.js` with `watchFolders` pointing to monorepo root and node\_modules.           |
| **Expired Tokens during Checkout**      | User gets kicked out during payment             | Single-flight refresh mutex in `ApiClient` refreshes JWT transparently without losing checkout state.  |
| **Slot Double-Booking Race Condition**  | Two users booking the same time slot            | Acquire 10-minute temporary reservation lock (`POST /customer/bookings/reservation`) prior to payment. |
| **Hardware Keystore Unavailability**    | App crash on older devices                      | Fallback gracefully to in-memory storage if `SecureStore.isAvailableAsync()` returns false.            |
